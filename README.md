# PDF → Word ด้วย OpenThai2.1-OCR-Markdown (RTX 3060 12GB)

รันทั้งหมดผ่าน Docker บน Windows ไม่ต้องติดตั้ง Python, pandoc หรือ Ubuntu บน WSL เอง

## 1. สิ่งที่ต้องมี
- **Docker Desktop** (ใช้ WSL2 backend) และเปิดโปรแกรมไว้
- **NVIDIA driver** ทดสอบด้วยคำสั่ง `nvidia-smi`
- **Git LFS** สำหรับดาวน์โหลดโมเดล ทดสอบด้วยคำสั่ง `git lfs version`
- พื้นที่ดิสก์ว่างราว 60 GB สำหรับ Docker image และอีก 5 GB สำหรับโมเดล
- ฟอนต์ **TH SarabunPSK** (ฟอนต์มาตรฐานหนังสือราชการ) บนเครื่องที่จะเปิดไฟล์ Word

## 2. ติดตั้ง (ทำครั้งเดียว)
รันคำสั่งทั้งหมดจากโฟลเดอร์ของโปรเจคนี้

```powershell
# ดาวน์โหลดโมเดล (2.7 GB) ลงโฟลเดอร์ model/
git clone https://huggingface.co/iapp/OpenThai2.1-OCR-Markdown-20261118 model

# สร้าง image ของ vLLM server (ครั้งแรกใช้เวลาราว 1 ชั่วโมง)
docker build -f docker/Dockerfile.server -t nemotron-parse:3.5.0.post8 model

# สร้าง image ฝั่ง client ที่ใช้รัน pdf2docx.py (มี pandoc, PyMuPDF, python-docx)
docker build -f docker/Dockerfile.client -t pdf2docx-client docker
```

### อัปเดตจากเครื่องที่ติดตั้ง OpenThai2.0 ไว้แล้ว
โมเดล 2.1 ใช้ไลบรารีชุดเดิม จึงไม่ต้อง build ใหม่ทั้งชั่วโมง แค่ดาวน์โหลดโมเดลใหม่แล้วอัปเดตแพ็กเกจใน image

```powershell
git clone https://huggingface.co/iapp/OpenThai2.1-OCR-Markdown-20261118 model-v21
docker build -f docker/Dockerfile.update -t nemotron-parse:3.5.0.post8 model-v21
docker build --no-cache -f docker/Dockerfile.client -t pdf2docx-client docker
```
แล้วเปลี่ยนชื่อโฟลเดอร์ให้รุ่นที่จะใช้เป็น `model` (หรือเปิด server ด้วย `.\docker\start-server.ps1 -Model model-v21`)

### OpenThai2.1 เทียบกับ 2.0 (ทดสอบในโปรเจคนี้)
- ตัวพิมพ์ในหนังสือราชการและตาราง: แม่นเท่ากัน (PDF ทดสอบที่มีเฉลยผิด 0.8% และ 1.7% เท่ากันทั้งสองรุ่น)
- ลายมือ: 2.1 แต่งข้อความน้อยลง เช่น ไม่เขียนชื่อเดือนลายมือเป็นตัวเลขมั่ว ๆ และหน้าลายมือล้วนมักออกเป็นหน้าว่าง
- ไฮไลต์จุดไม่มั่นใจลดลงราว 20% และสระอำเป็นตัวเดียวตั้งแต่ต้น
- หน้าว่างไม่ถูกส่งให้โมเดล จึงไม่มีข้อความที่โมเดลแต่งขึ้นบนหน้าว่าง
- 2.1 มองสำเนาเอกสารที่แปะบนหน้า (เช่น ใบเสร็จ) เป็นรูปภาพบ่อยขึ้น สคริปต์จะเก็บข้อความไว้เมื่อโมเดลอ่านได้ยาวและมั่นใจเกินครึ่ง
- 2.1 อ่านหมายเหตุตะแคงในแผนผังได้เอง สคริปต์จึงอ่านซ้ำแบบหมุนเฉพาะหน้าที่สแกนตะแคงทั้งหน้า
- บางครั้งโมเดลวนพิมพ์ข้อความเดิมซ้ำ สคริปต์จะยุบเหลือครั้งเดียวและไฮไลต์ไว้ให้ตรวจ

## 3. เปิด server
```powershell
.\docker\start-server.ps1
```
- ใช้เวลาราว 2 นาที เมื่อพร้อมจะขึ้นข้อความ `Ready`
- ใช้ VRAM ประมาณ 7 GB (60% ของการ์ด) และรับงานพร้อมกันได้ 8 หน้า ปรับได้ที่ `--gpu-memory-utilization` และ `--max-num-seqs` ในสคริปต์
- ตั้งเป็น FlashAttention 2 เพราะเวอร์ชัน 3 ที่โมเดลใช้เป็นค่าเริ่มต้นไม่รองรับ RTX 3060
- ปิด server เมื่อเลิกใช้ด้วย `docker stop nemotron-parse`
- ถ้า Windows ไม่ยอมรันไฟล์ `.ps1` ให้ใช้ `powershell -ExecutionPolicy Bypass -File .\docker\start-server.ps1`

## 4. แปลงไฟล์
```powershell
# ลองกับ 10 หน้าแรกก่อน เพื่อวัดความเร็วจริง
.\docker\convert.ps1 D:\งาน\เอกสาร.pdf --pages 1-10

# ทั้งไฟล์
.\docker\convert.ps1 D:\งาน\เอกสาร.pdf --workers 6
```
ผลลัพธ์อยู่ข้างไฟล์ PDF:
- `เอกสาร.docx` คือไฟล์ Word
- `เอกสาร.pages/` คือ Markdown ของแต่ละหน้า (`page_00001.md`, ...)

ไม่ต้องใส่ `-o` เพราะสคริปต์ตั้งชื่อไฟล์ผลลัพธ์ตามชื่อ PDF ให้เอง

### ไฮไลต์จุดที่ระบบไม่มั่นใจ
ข้อความที่โมเดลมั่นใจต่ำกว่า 80% จะถูกไฮไลต์สีเหลืองใน Word และเขียนเป็น `==ข้อความ==` ในไฟล์ Markdown ของแต่ละหน้า ใช้เป็นจุดเริ่มตรวจทาน

- **จับได้**: ตัวอักษรที่ไม่ชัด ลายมือ ตัวเลขที่อาจผิดตำแหน่ง และเซลล์ตารางที่โมเดลไม่แน่ใจเรื่องการผสานเซลล์ (ไฮไลต์ทั้งเซลล์)
- **จับไม่ได้**: คำที่โมเดลอ่านผิดแบบมั่นใจ จุดที่ไม่ไฮไลต์จึงยังอาจผิดได้ และข้อความที่หายไปทั้งบรรทัดจะไม่มีอะไรให้ไฮไลต์
- ปรับเกณฑ์ด้วย `--confidence` เช่น `--confidence 0.9` ไฮไลต์มากขึ้น, `--confidence 0` ปิดไฮไลต์
- เมื่อตรวจแล้ว ลบเครื่องหมาย `==` ในไฟล์ `.pages/` แล้วสร้าง Word ใหม่ด้วย `--from-md` ไฮไลต์จุดนั้นจะหายไป

### การจัดหน้าให้ใกล้ต้นฉบับ
โมเดลบอกตำแหน่งของทุกบล็อกบนหน้า สคริปต์ใช้ข้อมูลนี้จัดหน้า Word ให้ใกล้ต้นฉบับ (เป้าหมายราว 90% ไม่ใช่ตรงทุกจุด)
- หนึ่งหน้า PDF เป็นหนึ่งหน้า Word ขนาด A4 แนวตั้งหรือแนวนอนตามต้นฉบับ
- ขอบกระดาษวัดจากต้นฉบับ ถ้าใกล้มาตรฐานหนังสือราชการ (ซ้าย 3 ซม. ขวา 2 ซม.) จะใช้ค่ามาตรฐาน
- ขนาดตัวอักษรประมาณจากต้นฉบับ ถ้าใกล้ 16 พอยต์จะใช้ 16 พอยต์ ระยะบรรทัดหนึ่งเท่า
- บล็อกที่อยู่กึ่งกลางหรือเยื้องขวา (หัวเรื่อง คำลงท้าย ลายชื่อ) คงตำแหน่งไว้ รวมถึงระยะห่างระหว่างบล็อก
- การขึ้นบรรทัดภายในบล็อกคงไว้ตามต้นฉบับ ยกเว้นย่อหน้ายาว ซึ่งรวมบรรทัดให้ Word ตัดบรรทัดเอง และย่อหน้าบรรทัดแรก 2.5 ซม.
- ตารางได้ความกว้างและขนาดตัวอักษรที่คำนวณให้พอดีหน้า
- หน้าที่เนื้อหาเต็มเกือบถึงขอบล่าง จะลดขนาดตัวอักษรและระยะห่างลงเล็กน้อยเพื่อไม่ให้ล้นไปหน้าถัดไป

ข้อมูลตำแหน่งเก็บในไฟล์ Markdown รายหน้าเป็นคอมเมนต์ เช่น `<!--b Text 0.142,0.137,0.911,0.186-->` (ชนิดบล็อกและพิกัด) แก้ข้อความใต้คอมเมนต์ได้ตามปกติ ถ้าลบคอมเมนต์ บล็อกนั้นจะจัดแบบเรียงต่อกันธรรมดา

ข้อจำกัด
- ย่อหน้าจัดชิดซ้าย ไม่ได้กระจายแบบไทย เพราะ Word ที่ไม่มีตัวตัดคำไทยจะยืดตัวอักษรจนผิดรูป เปลี่ยนได้ที่ค่า `JUSTIFY_BODY` ใน `pdf2docx.py`
- ตารางที่วางคู่กันซ้าย-ขวาในต้นฉบับ จะรวมเป็นตารางเดียวที่มีคอลัมน์คั่นกลางแบบไม่มีเส้นขอบ จึงดูเป็นสองตารางเหมือนเดิม
- บล็อกข้อความที่อยู่บรรทัดเดียวกันซ้าย-ขวาในต้นฉบับ จะเรียงเป็นบน-ล่าง
- ตารางใหญ่มากหรือหน้าที่โมเดลอ่านพลาด อาจล้นเป็นสองหน้า
- หน้าที่ต้องแบ่งครึ่งอ่าน และข้อความตะแคงที่นำมาต่อท้าย จะจัดแบบเรียงต่อกันธรรมดา
- ตรวจหน้าจริงได้ด้วย `docker\word-preview.ps1 ไฟล์.docx ผล.pdf` (ต้องมี Word) ซึ่งจะบอกว่าหน้าไหนล้น

### รูปภาพ แผนที่ และกราฟ
ส่วนที่โมเดลจัดเป็นรูปภาพหรือกราฟจะถูกแทนด้วยกรอบสี่เหลี่ยมเขียนว่า "รูปภาพ" ขนาดและตำแหน่งตามต้นฉบับ ตัวรูปและข้อความในรูปไม่ถูกนำมาใส่ เพราะข้อความที่โมเดล "อ่าน" จากรูปมักไม่มีอยู่จริง
ในไฟล์ Markdown จะเห็นเป็นบรรทัด `[รูปภาพ]` ลายเซ็นไม่ถูกถอดเป็นข้อความอยู่แล้ว ถ้าต้องการเก็บข้อความในรูปไว้แทนกรอบให้เติม `--keep-pictures`
ข้อจำกัด: ภาพหน้าจอที่มีตารางอยู่ข้างใน โมเดลอาจจัดเป็นตารางและยังหลงเหลืออยู่ ซึ่งมักถูกไฮไลต์หนาแน่นให้เห็น

### หน้าตะแคงและข้อความตะแคง
- **หมายเหตุตะแคงในแผนผัง**: OpenThai2.1 อ่านได้เองโดยไม่ต้องหมุนภาพ
- **หน้าที่ทั้งหน้าสแกนมาตะแคง**: สคริปต์อ่านซ้ำโดยหมุน 90 องศาทั้งสองทาง และใช้ผลนั้นแทนเมื่อโมเดลมั่นใจกว่าชัดเจน ผลที่ไม่มั่นใจจะไม่ถูกนำมาใช้
- หน้าที่กลับหัว 180 องศายังไม่รองรับ
- ปิดการอ่านซ้ำได้ด้วย `--no-rotate` (หน้าเว็บ: ตั้ง `OCR_ROTATE=0`)

### แก้ผล OCR เองแล้วสร้าง Word ใหม่
แก้ไฟล์ใน `เอกสาร.pages/` แล้วรันคำสั่งด้านล่าง จะสร้าง Word ใหม่โดยไม่ OCR ซ้ำ
โฟลเดอร์ของ PDF ถูกมองเห็นใน container เป็น `/data` จึงต้องอ้างโฟลเดอร์ `.pages` ด้วยเส้นทางนั้น

```powershell
.\docker\convert.ps1 D:\งาน\เอกสาร.pdf --from-md /data/เอกสาร.pages
```

### รันด้วย CPU โดยไม่ใช้ server
เติม `--local` สคริปต์จะโหลดโมเดลเข้ามารันเองด้วย Transformers ไม่ต้องเปิด vLLM server และไม่ใช้ GPU

```powershell
.\docker\convert.ps1 D:\งาน\เอกสาร.pdf --local
```
- ช้ากว่า GPU มาก: บนเครื่องนี้ใช้ราว 2-3 นาทีต่อหน้า (GPU ราว 3-5 วินาที) และทำทีละหน้า
- ผลอาจต่างจากการรันผ่าน server เล็กน้อย เพราะใช้วิธีถอดรหัสคนละแบบ
- กำหนดจำนวน thread ได้ด้วย `--threads`

### ใช้งานผ่านหน้าเว็บ
```powershell
# ใช้ GPU (เร็ว): เปิด vLLM server ก่อน แล้วเปิดเว็บด้วย -Gpu
.\docker\start-server.ps1
.\docker\start-web.ps1 -Gpu

# ใช้ CPU อย่างเดียว ไม่ต้องเปิด vLLM server
.\docker\start-web.ps1
```
เปิด <http://localhost:8080> แล้วอัปโหลด PDF รอจนแปลงเสร็จ และกดดาวน์โหลดไฟล์ Word
- **โหมด GPU**: ราว 2-5 วินาทีต่อหน้า ส่งทีละ 6 หน้า (ไฟล์ 206 หน้าใช้ราว 12 นาที) หัวหน้าเว็บจะขึ้นว่าใช้ GPU
- **โหมด CPU**: ราว 2-3 นาทีต่อหน้า ไฟล์ 100 หน้าใช้หลายชั่วโมง ตัวเลขความคืบหน้าจะขยับช้ามากจนดูเหมือนค้าง
- สลับโหมดได้โดยรันคำสั่งเปิดเว็บใหม่ งานที่ค้างอยู่จะทำต่อจากหน้าที่เสร็จแล้ว
- อัปโหลดได้หลายไฟล์ ระบบแปลงทีละไฟล์ตามคิว เลือกช่วงหน้าได้ และยกเลิกหรือลบงานได้
- ไฟล์ที่อัปโหลดและผลลัพธ์เก็บในโฟลเดอร์ `webdata/` ปิดแล้วเปิดเว็บใหม่รายการยังอยู่ และงานที่ค้างจะทำต่อจากหน้าที่ค้าง
- เข้าได้จากเครื่องนี้เท่านั้น (ผูกกับ `127.0.0.1`) และไม่มีระบบล็อกอิน
- เปลี่ยนพอร์ตด้วย `.\docker\start-web.ps1 -Port 9000` ปิดเว็บด้วย `docker stop pdf2docx-web`

### ติดตั้งหน้าเว็บบน Ubuntu Server
ชุดติดตั้งแบบ CPU สำหรับ server อยู่ในโฟลเดอร์ `deploy/` (image ขนาด 2.4 GB ไม่ต้องมีการ์ดจอ มีล็อกอิน)
ดูขั้นตอนใน [deploy/README.md](deploy/README.md) ไฟล์ที่ต้องคัดลอกขึ้น server รวมไว้ใน `dist/pdf2docx-web.tar.gz`

### ทดสอบว่าระบบทำงาน
สร้าง PDF ภาษาไทย 2 หน้า (มีหัวข้อ รายการ และตารางผสานเซลล์) แล้วแปลง

```powershell
docker run --rm -v "${PWD}:/data" --entrypoint python3 pdf2docx-client /data/docker/make_test_pdf.py /data/test/test.pdf
.\docker\convert.ps1 .\test\test.pdf
```

## ความสามารถ
- เรนเดอร์ PDF เป็นภาพทีละหน้า และเก็บภาพไว้บนดิสก์ไม่เกิน `workers×2` หน้า จึงรองรับไฟล์ 100MB ได้
- หน้าที่เป็นภาพสแกนจะส่งให้โมเดลที่ความละเอียดเดิมของภาพ ไม่ขยาย และย่อเฉพาะเมื่อใหญ่เกิน 1664×2048 px
- บันทึกผล OCR ของแต่ละหน้าไว้ใน `<ชื่อไฟล์>.pages/` ถ้าสคริปต์หยุดกลางทาง รันคำสั่งเดิมซ้ำจะทำต่อจากหน้าที่ค้าง
- หน้าที่ OCR ไม่สำเร็จจะไม่ถูกบันทึกลงแคช สคริปต์แจ้งเลขหน้าตอนจบ และรันคำสั่งเดิมซ้ำจะลองใหม่เฉพาะหน้าเหล่านั้น
- ถ้าหน้าไหนยาวจนชนขีดจำกัด token จะแบ่งเป็นครึ่งบนกับครึ่งล่างแล้ว OCR ใหม่ให้อัตโนมัติ
- ตาราง HTML ที่มี rowspan/colspan แปลงเป็นตาราง Word ที่ผสานเซลล์จริง มีเส้นขอบ และแถวหัวตารางซ้ำทุกหน้า
- แปลงสระอำที่โมเดลเขียนแยกเป็นสองตัวอักษร (นิคหิต + สระอา) ให้เป็นตัวอักษรมาตรฐาน เพื่อให้ค้นหาคำใน Word ได้
- จัดหน้า Word ให้ใกล้ต้นฉบับ: หน้าต่อหน้า แนวตั้ง/แนวนอน ตำแหน่งบล็อก และกรอบแทนรูปภาพ ตามมาตรฐานหนังสือราชการ (TH SarabunPSK 16pt)

## ข้อจำกัดที่ทราบ
- ตารางตัวเลขจากภาพสแกน (เช่น รายการเดินบัญชี) อาจได้ค่าผิดแถวหรือหาย ต้องตรวจตัวเลขกับต้นฉบับทุกครั้ง
- ตัวหนาและตัวเอียงมักหายไป ทั้งในย่อหน้าและในตาราง
- รูปภาพ แผนที่ และกราฟ เป็นกรอบว่างเขียนว่า "รูปภาพ" ตัวรูปและลายเซ็นไม่ถูกนำมาใส่ใน Word
- ระดับหัวข้ออาจไม่ตรงกับต้นฉบับ และบรรทัดสั้นที่อยู่ติดกันอาจถูกรวมเป็นย่อหน้าเดียว
- ตารางที่มีหัวตารางหลายแถว จะซ้ำเฉพาะแถวแรกเมื่อขึ้นหน้าใหม่
- ตารางซ้อนตารางยังไม่รองรับ

## ไฟล์ในโปรเจค
| ไฟล์ | หน้าที่ |
|---|---|
| `pdf2docx.py` | สคริปต์หลัก: PDF → ภาพ → OCR → Markdown → Word |
| `webapp.py`, `web/index.html` | หน้าเว็บสำหรับอัปโหลด PDF และดาวน์โหลด Word (รันด้วย CPU) |
| `docker/start-web.ps1` | เปิดหน้าเว็บที่พอร์ต 8080 |
| `webdata/` | ไฟล์ที่อัปโหลดผ่านเว็บและผลลัพธ์ |
| `docker/Dockerfile.server` | image ของ vLLM server (ไม่รวมไฟล์โมเดล ใช้การ mount โฟลเดอร์ `model/`) |
| `docker/Dockerfile.client` | image สำหรับรัน `pdf2docx.py` |
| `docker/start-server.ps1` | เปิด server ด้วยค่าที่เหมาะกับ RTX 3060 |
| `docker/convert.ps1` | แปลง PDF หนึ่งไฟล์ |
| `docker/make_test_pdf.py` | สร้าง PDF ทดสอบภาษาไทย |
| `docker/word-preview.ps1` | ให้ Word ส่งออก PDF และบอกว่าหน้าไหนล้น (ต้องมี Word) |
| `model/` | ไฟล์โมเดลจาก Hugging Face (ดาวน์โหลดในขั้นตอนที่ 2) |

## รันโดยไม่ใช้ Docker
ทำได้บน Linux หรือ WSL2 ที่มี Python 3.12: ติดตั้งแพ็กเกจจากโฟลเดอร์โมเดลด้วย
`pip install "./model[vllm,client]"` ติดตั้ง `pymupdf python-docx markdown` และ pandoc 3.x
แล้วรัน vLLM ด้วยตัวเลือกชุดเดียวกับใน `docker/start-server.ps1`
วิธีนี้ยังไม่ได้ทดสอบบนเครื่องนี้ รายละเอียดอยู่ใน `model/docs/serving-reference.md`
